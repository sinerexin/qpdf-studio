# 第三步五环节统一流程（2026-11-01）

## 用户确认的界面

- 顶部只保留“返回编辑”。移除“验证结果与证书”“B 签署设置”“自动生成参数”三个入口。
- 原先五个交叉重叠的工具替换为：①读取 A 参数、②生成 B 密钥、③生成 B 证书、④签署 B、⑤检查与对照。
- 中央“生成新签名”继续一键完成全部五环节，不需要用户逐项准备。
- 证书卡片和公钥卡片的生成动作也接到同一第三/第二环节，不再从旁路产生另一套凭据。

## 真实工序与中间结果

1. **读取 A 参数**：统一读取实际 A，提取当前所选签名的可沿用参数；名称、算法、主体属性来自实际报告，不来自显示排版。点击该按钮开始新一轮流程。
2. **生成 B 密钥**：只生成新密钥并显示公钥；私钥对象只在后台会话内存中，第三环节统一加密保存，不放入 UI 快照、JSON 或记录。
3. **生成 B 证书**：使用第二环节的同一把密钥，生成证书、P12、加密 PEM 及 Windows 托管密码记录，不另造另一套密钥。
4. **签署 B**：读取本轮凭据，签署当前累计修改后的 B，保存独立新文件。此阶段完成不等于第五阶段检测通过；右侧保持待检查。
5. **检查与对照**：重读最终签署 B，以与 A 相同的检查入口形成真实报告，按证书指纹定位本次签名。检测失败保留产物并显示错误，不伪造通过。单独点击该按钮没有本轮输出时只检查当前 A/B，不暗中生成签名。

`SigningStages.run_to()` 是一键和分项共用的执行器。分项点击自动完成缺失前置步骤；已有中间材料复用，不因查看已完成一步再次生成。重新导入 A/B 或换用其他 A 签名参数时开始对应新会话。已有输出和凭据不删除、不覆盖。

一键按钮在已完成部分步骤时自动接续；全流程已完成后再次点击才开始生成另一份新签名。界面显示本轮完成进度，原稿和实际 B 的验证结果分别保存。

移除的是界面入口，不破坏既有后端接口或用户凭据。本次不新增 PDF 旁修改记录、不上传文件、不改变真实检查结果。
