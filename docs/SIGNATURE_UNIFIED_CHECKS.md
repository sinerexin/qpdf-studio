# A/B 统一签名检查与显示

## 本次改动

- A（原稿）和 B（编辑/签署稿）使用相同的检查函数，不把文件角色作为通过/失败条件。
- 右侧验证区统一显示：信息读取、签名结构、字节摘要、数学签名、身份信任。
- 读取完整只表示当前配置范围内数据读取完成；部分读取不等于签名无效。
- 签名结构检查 ByteRange 数值与范围，以及它的空洞是否对应当前签名 Contents 原始位置。
- 字节摘要显示一致/不一致/无法计算；数学签名显示有效/无效/未验证；身份信任独立显示。
- 字段关联、覆盖范围、后续修订、原始验证器字段继续保留在详细依据中。

## 精确位置与限制

只从当前解析器 xref 返回的普通对象偏移读取，不全文件搜索首个同号对象。
原始字符串边界包含 `< >` 或 `( )`，使用半开区间 `[start, end)`；通过 PDF 词法读取顶层键，兼容转义 name 和 literal string。
同时核对原始字典与当前解析值的 ByteRange/Contents，拒绝猜测重复键含义。
压缩对象、直接嵌套字典、加密文件、非标准多段范围、无法定位的对象明确显示“无法确定”。
结构“正常”仅指上述检查范围，不是完整 PDF 合规审计；摘要比较结果不会因位置异常被隐藏或改写。
追加字节、位置异常、摘要不一致都不独立证明修改原因、操作者或恶意。
未关联字段树的对象仍能显示证书、公钥和摘要，但尚未完成的数学验签保留“未验证”。
