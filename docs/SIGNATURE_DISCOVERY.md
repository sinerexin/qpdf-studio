# 签名对象补充识别：代码说明

## 原因与本次范围

旧路径只从 `/AcroForm/Fields` 枚举签名。字段树为空、断链或未挂接时，独立 `/Sig` 对象不会进入 UI。
本次保留字段路径，并增加当前交叉引用对象扫描；不修改用户 PDF，不补写字段，不重存，不上传，不读取独立私钥。

## 新增或修改的代码做什么

1. `signature_discovery.py`
   - `reference_key`：以对象号/代号识别同一对象，避免正常签名重复出现。
   - `discover_signature_objects`：合并交叉引用中的引用，读取当前有效对象；识别 `/Sig`、`/DocTimeStamp`、或同时具有 `/ByteRange` 与 `/Contents` 的候选；直接嵌套字典记录“所在对象 + 路径”，不冒充独立对象号。
   - 不执行页面流、JavaScript、附件或网络请求；不把文件里的普通关键字文本当作签名。
   - 字段树枚举出错后仍执行扫描。每个对象单独处理错误，损坏一个不跳过其他对象。
   - 资源预算为 100000 个对象引用、200000 个直接节点、32 层、20 秒、最多 128 个签名候选（沿用证据展开总量）；达预算明确显示扫描不完整，不下“无签名”结论。
   - `detached_digest_evidence`：对支持的 detached 容器按合法 ByteRange 分块读取源字节，比较 CMS messageDigest。负数、重叠、非整数、越界、错误属性均显示错误或未判断；不把摘要一致变成数学签名或身份信任通过。
2. `signature_evidence.py`
   - `_extract_cms`：从旧字段提取函数中抽出共用的 CMS、证书、公钥读取逻辑。正常字段仍沿用原签署证书选择规则；对象扫描按实际 SignerInfo 选择证书，不拿第一张证书假定为签署者。
   - `_discovery_info`：记录对象引用、直接路径和未关联状态；解析器对象本身不放进 JSON。
   - `_extract_unlinked`：展示签名字典、ByteRange、容器、证书、公钥、摘要算法等真实数据，并说明未关联字段树；不创建虚假表单字段。
   - `collect_signature_evidence`：原字段路径与补充对象路径接起来，按对象引用/已解析直接字典去重。
   - `read_signature_audit`：分开保存字段验证数量、实际检测数量、未关联对象数量；不把发现数量当作验证通过数量。
3. `signature_presentation.py`
   - 未关联对象显示“字节摘要对照 / 数学签名未验证 / 身份信任未建立 / 字段未关联”。摘要匹配仅显示“摘要一致”，不显示整份 PDF 验证通过。
   - 扫描不完整时不显示“无数字签名”。
4. `qt_signature_evidence.py`
   - A/B 下拉框和详情可选对象扫描得到的数据；读完提示使用检测数量，不会再被字段验证数量 0 覆盖。
   - 完整信息增加发现来源、关联状态、补充字节摘要对照、扫描范围与错误。
5. `signature_card_data.py`
   - 卡片显示识别到的证书与公钥，并明确标注“对象扫描发现，未关联字段树”。
6. `automatic_signing.py`
   - 仅修改读完后的状态提示，使其与 A/B 详情一致；未改动生成密钥、自动密码、证书或签署过程。
7. 测试代码
   - 新增纯合成回归用例：空字段树发现、正常对象去重、直接嵌套路径、对象错误隔离、预算提示、合法/非法 ByteRange、摘要匹配与不匹配、未知不显示通过、卡片显示来源。
   - 不把用户 PDF、证书和银行正文复制进源码或测试。

## 尚未覆盖的内容

- 本次读取当前交叉引用可解析的对象，不回放已释放或被覆盖的每个历史对象版本；交叉引用之外完全未登记的字节碎片不自动归属为有效签名。
- 未关联字段树对象未执行完整 PDF 字段验签；补充摘要比较不验证 CMS 签名、证书链、撤销、可信时间戳、页面绑定或业务真实性。
- 旧式签名、文档时间戳、多个 SignerInfo 等不适用普通 detached 摘要规则时明确未判断，不套用错误规则。

## 安装与检查

新增逻辑均带中文注释。按此前用户要求，仅语法、导入、接线和部署 SHA 检查；未执行 pytest、GUI、新版识别功能运行验收或网络验证。原 PDF 未修改。
