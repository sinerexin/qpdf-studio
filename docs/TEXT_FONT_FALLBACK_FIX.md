# 文字缺字生成失败：本次中文改动记录

## 已确认的原因

原来的原字体编码函数在找不到唯一编码、或字符未出现在原字体子集时直接抛通用错误。
自动字体入口只识别 WinAnsi 字体；中文嵌入子集没有接入自动替换。
旧换字体实现还只接受简化的独立 Tj，而当前失败选区实际是 TJ 数组中的字符串，所在文字对象有颜色、线帽和虚线设置。
因此不是签名/证书阻止了编辑，而是字体能力判断直接变成了整个编辑任务失败。

## 逐项改了什么

1. **font_cmap.py**：删除缺字分支中原先的两处通用 `raise ValueError`，新增 `encode_if_available`；没有可用原编码时返回 `None`。
   兼容的低层 `encode` 接口通过 `FontEmbeddingRequired` 告知调用者“需要嵌入字体”。这是可接续的内部信号，不是自动模式的最终失败。
2. **replace_text.py**：西文字体无法编码新字时也使用同一个内部信号，避免中文、西文走两套逻辑。
3. **qt_context_editor.py**：删除“只有 winansi-type1 才允许进入自动字体处理”的分支；优先尝试原字体，自动模式捕获换字体信号，继续调用嵌入处理。
   把 TJ 的字符串下标传给底层，并修正界面提示。用户主动选择“仅原字体”时仍按该选项工作。
4. **font_replacement.py**：支持独立单行 Tj 和 TJ 里的指定字符串；不再因同一文字对象带颜色、线帽或虚线设置就直接拒绝。
   嵌入本机黑体，替换实际文字显示操作，保留原 Tm、字号、颜色和周边操作，不画白块、不保留被替换字符串作为底层正文。
   TJ 中其他字符串的原字节和数字字距保留；根据新旧字宽补偿后续片段位置。生成器的默认字体/定位不覆盖源文件的文本状态。
5. **测试用例**：补充中文子集自动接续、仅原字体模式、非字体错误不误吞、TJ 新中文字、TJ 前后片段与字距保留用例，更新旧错误文本断言。
