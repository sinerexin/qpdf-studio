# 第三步证书工具拆分及设置接线（2026-11-01）

## 可见按钮及实际功能

“更多证书工具”不再作为第三步的下拉菜单显示，改为导航栏下方两行独立按钮：

| 按钮 | 实际操作 | 完成后 |
| --- | --- | --- |
| 生成公钥 / 加密私钥 | 打开已有密钥/证书生成器，可设置名称、算法、有效期、输出目录 | 新 P12 绑定为 B 的待用凭据，公钥资料显示在 B 信息中 |
| 修改 / 重新签发证书 | 选择已有证书/对应密钥目录，设置新名称及有效期，另存新证书 | 新 P12 同样绑定 B，既有证书不原位改写 |
| A / B 签名对照 | 回到主界面 A/B 信息，并调用现有统一读取接口重检 | 两侧信息在中央，验证结果在右侧；不再使用遗漏孤立对象的旧对照档案 |
| 按 A 算法生成密钥 | 读取 A 当前选中的真实签名报告，提取 RSA 位数或 EC 曲线 | 预填新密钥生成器，结果仍绑定 B；不要求 A 的验签/信任先通过 |
| 重新签发并签署 B | 复用现有“已有密钥生成新证书再签署”窗口 | 实际生成新凭据和签署文件后加载 B |

按钮各自有固定键和说明，不会因循环闭包把所有点击接到最后一个操作。工具异常在窗口显示，不只输出到 pythonw 的标准错误。

## B 签署设置的实际修复

原设置页底部按钮实际连接 `shell.generate_b_signature`，所以即使上方选择了 P12 和输出位置，点击仍会走自动重建凭据，忽略这些设置。

现改为：

- 设置页底部“使用所选凭据签署 B…” → `shell.sign_b_with_selected_credentials` → `w.sign_active`，使用 `selected_signing_credential`、`selected_signing_output`。
- 已选凭据时不重新生成一套；没有选时复用现有文件选择流程。
- 本机托管密码自动读取，外部凭据按需输入密码。
- “修改/重新签发”和“重新签发并签署”也接入同一托管密码机制；新 P12 保留 Windows 用户保护记录，后续签署无需猜程序自动密码。只读取用户选定目录中的本程序记录，不搜索其他凭据。
- 使用已有凭据签署成功后，将实际用到的 P12 重新绑定到新 B，便于继续操作；重新签发并签署的结果也回到当前 A/B 信息和验证区。
- 已签署过一次后，新选择的输出位置优先显示，不再被上一份已保存输出覆盖显示。
- 中央“生成新签名”仍保留已成功使用的一键全自动流程，和手动凭据设置互不混淆。
- “自动生成参数…”单独可见，供调整一键生成的名称、算法和输出位置。
- 工具和选凭据签署的模态窗口期间暂停尚未开始的自动读取，避免确认后执行器被占用而丢弃操作；返回后恢复读取调度。
- 第三步工具栏按内容计算高度，不再被旧 116px 高度裁切；其他步骤保留原高度。

## 保留与检查边界

未改 A 原文件、未自动上传、未生成 PDF 旁修改记录，不改动真实验签结果。新逻辑中文注释，说明实际工序而不把证书声明冒充独立信任。

按此前要求，本轮仅做语法、模块导入、静态接线与安装 SHA 核对。回归用例已编写但不执行；未启动/重启 GUI，未实际生成密钥或签署 PDF。用户保存当前工作后重开桌面最新版加载更新。
